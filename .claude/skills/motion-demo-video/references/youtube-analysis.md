- **매크로 줌**: 입력창에 문장이 타이핑되는 동안 카메라가 아주 크게 확대해 글자를 따라 가로로 팬 → 줌아웃해서 입력창 전체.

## D. 키네틱 타이포 교육 영상 (Opus 영어 7:52–8:27, 한국어 9:12–9:43)

- 가사가 **단어 단위로 쌓이고 남음**: 문장이 화면에 누적되다 마지막에 요약판이 됨(VISIBILITY / KEEP TO THE RULES / CONSISTENCY).
- **단어가 뜻대로 움직임**: GUESS 글자가 흔들림, SPIN이 회전하며 날아옴, CONSISTENCY는 외곽선 글자 여러 장이 겹쳐 하나의 실선 글자로 합쳐짐, FAIL?은 화면 반쪽이 초록으로 갈라짐, EXPERT는 박스가 그려짐.
- **UI 목업이 배우 역할**: Save 버튼 클릭 → "?" 떠다님 → 스피너 → 원형 진행선 → Saved. 같은 버튼이 장면을 건너 계속 등장.
- 화면 하나가 많은 화면으로 **줌아웃**(EVERY SCREEN PLAYS: 기울어진 격자).
- 마지막에 **초록 플러드**(배경 전체가 강조색으로 덮임)로 클라이맥스.
- 상단 HUD: `02 / 10`, 섹션 이름, 진행 점.

## F. 지금 스킬에 빠져 있는 것

1. 전환 규칙이 "연속적으로" 한 줄뿐. **구체적인 전환 기법 목록**이 없음 (오브젝트 연속, 배경 확장, morph, 수축→폭발, 파티클 집결, metaball, 매크로 줌 연속, 배경 물들이기, 프레임 고정 내용 교체, 모션 블러 휩).
2. **주인공 오브젝트(hero object)**를 정하는 단계가 없음. 쇼릴의 점, Flowdeck의 NOW 점처럼 제품에 원래 있는 요소를 골라 처음부터 끝까지 끌고 가야 함.
3. **고정 틀**(HUD, 하단 캡션 칩) 개념이 없음.
4. **가상 카메라** 개념이 없음. 실제 화면 녹화 위에서 줌인/팬/줌아웃을 이어가는 방식.
5. 타임라인 시트의 `transition out` 칸에 무엇을 써야 하는지 기준이 없음. 하드 컷이 허용되는 곳(몽타주, 박자 강조)도 정의 안 됨.
6. 박자(BPM) 그리드에 전환을 맞추는 구체 방법이 없음.
